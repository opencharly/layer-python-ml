# 2026.323.1851 — fix(python-ml): require the layer-cuda release that dropped the driver layer

## Summary

`python-ml`'s `require:` moves from `layer-cuda:v2026.321.1520` to
`layer-cuda:v2026.323.0252` — the release that dropped `require: layer-nvidia`
(opencharly/layer-cuda#30).

The old require is target-blind: it pulled the VM driver layer into every pod that
composes this toolkit. It also blocked opencharly/distro-fedora#128:
`immich-ml-cdi` must declare the current `layer-cuda`, and with this candy still
requiring the previous one the two tags land in ONE box scope, where
`charly box validate` refuses to choose. Moving the require removes the conflict
at its source, exactly as #13 did when it moved `.290.1513 -> .321.1520` for the
distro-cachyos boxes.

## Change classification

Every consumer of `python-ml` composes the CUDA toolkit at `v2026.323.0252`
instead of `v2026.321.1520`; the newer release no longer pulls the VM driver layer,
so a pod that composes it stops baking a driver it should receive through CDI. A VM
guest that relies on the transitively required driver composes `layer-nvidia`
itself (`opencharly/vm-nvidia`). Rollback is the one-line revert of this pin.

**Breaking change + rollback:** the toolkit coordinate consumed by every
`python-ml` consumer moves; roll back by reverting the single `require:` line,
which restores the previous toolkit and its driver dependency.
